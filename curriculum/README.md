# Curriculum

21 days, three weeks, one day at a time.

## Structure

Every day has the same seven sections:

| Section | Purpose |
|---|---|
| **Objective** | What you will be able to do afterwards |
| **Concepts** | Theory, from first principles |
| **Architecture** | How this appears in a production system |
| **Exercise** | The hands-on task |
| **Deliverable** | What must exist in the repo afterwards |
| **Reflection** | Questions to answer in `journal/` |
| **Interview Question** | A Sierra-style question, with notes on what a strong answer contains |

## Completion rule

A day is done when the **deliverable exists** and the **journal entry is written**. Not before. Reading a day is not doing a day.

## If you fall behind

Do not skip days to catch up. The dependencies are real — day 17 is only possible because days 3–13 forced the primitives into existence. A 30-day run of all 21 days beats a 21-day run of 14.

## If a day is too easy

Do the exercise anyway, then go further: harder adversarial cases, a second implementation to compare, or the "beyond" suggestions in day 21. The reflection questions are calibrated for someone who did the full exercise.
