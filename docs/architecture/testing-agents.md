# Testing an Agent

**Status:** standard · **Applies to:** every agent built in this repository · **Written:** day 11

What test layers a new agent needs, in what order, and the one that gets skipped.

---

## The finding this exists because of

On project 03, **ten of eleven defects were found by a person typing at the agent.** None was found by the suite. Among them:

| Found by hand | Consequence if shipped |
|---|---|
| `"no thanks"` triggered `cancel_booking` | A member declining a memory offer loses their tee time |
| `"just me"` booked as four players, three guests | $60 of fees nobody agreed to |
| A club question answered with no tool call | The abstention branch bypassed entirely |
| A booking made against **2025** | "Nothing free on Saturday" — about a Friday last year |

There was a structural reason, and it was one line:

```ts
const response = await client.messages.create({ ... });   // hardcoded
```

`agent.ts` was **1112 lines — the largest file in the project — with zero tests.** Testing the loop needed an API key, a network and a non-deterministic model, so it never happened. Which is this repo's own review question, failing:

> *"Is it testable without an LLM? If not, the logic and the model call are tangled."*

---

## The four layers

| Layer | Catches | Needs a model? | Cost |
|---|---|---|---|
| 1. **Pure functions** | our logic regressing | no | free |
| 2. **The loop, injected model** | the loop's own behaviour | no | free |
| 3. **Conversational golden set** | the model doing something dangerous | **yes** | cents |
| 4. **Hostile fake API** | the tool layer under failure | no | free |

Layers 1, 2 and 4 prove *our code* does not regress. **Only layer 3 can discover what a real model does**, and it is the one that gets skipped because it is the only one that costs money.

---

## Layer 2 — make the model injectable on day one

```ts
export type ModelFn = (req: {...}) => Promise<{ content, stop_reason }>;

export async function turn(s: Session, input: string, model: ModelFn = liveModel)
```

**Retrofitting this is the blocker that stops the tests existing.** Write it into the first version of any agent loop and layer 2 costs nothing thereafter.

What it makes testable, all without a model: preamble suppression, terminal-tool handling, reply ordering, step ceilings, short-circuits, and every "the loop must not do X" rule.

## Layer 3 — the conversational golden set

### Gate on tool calls. Report on prose.

Every dangerous thing an agent has done in this repository was **visible in a tool argument and invisible in the reply**:

```
book_tee_time({partySize: 4, guests: 3})    the member said "just me"
cancel_booking({...})                       they had declined a memory offer
check_availability({date: "2025-08-29"})    last year, and a Friday
remember_preference({...})                  fired on an aside
```

Day 9 spent seven assertion errors gating on wording and ended with the rule. Gating on a fuzzy signal is how a suite gets switched off.

**The exception:** reply text *generated by code* may be gated — `"$40"` computed from `fees.yaml` is as deterministic as a tool argument. The split is about determinism, never about which layer a string lives in.

### Assert on outcomes, not attempts

A guard that corrects a bad argument produces both the wrong attempt and the right outcome in the trace. An eval matching attempts once **failed a case where the agent had behaved perfectly** — which would have taught us to distrust a working guard.

Record refused calls as **near-misses** and report them: *"the model never does this"* and *"the model does this and we catch it"* are different facts, and only one of them means you can remove the guard.

### Repeat anything destructive

> **A single run of a probabilistic failure is a weak test.**

Disabling the yes/no short-circuit left the suite green — that run, the model happened not to reach for `cancel_booking`. With three runs it failed on the third, putting the rate near **one in three**: a single-run suite misses it twice out of three while reporting green.

Any case asserting that a destructive tool was **not** called earns `runs: 3`. Failures merge rather than average — there is no *"mostly did not cancel the member's booking"*.

### Keep it small

Seven cases, eleven runs, pennies. **A suite that costs a dollar is a suite nobody runs, and a suite nobody runs does not exist.**

### Every case names the incident

```
why: 'A member said "the 9:20, just me. I usually play early with the same
      three lads" and was booked for four with three guests — $60 of fees
      nobody agreed to.'
```

Printed on failure. Six months later, the reason a case exists is worth more than the assertion.

## Controls, for every layer

**Never trust a suite that has only ever been green.** Break each mechanism, confirm a test fails, record the result.

This has caught three false-confidence cases here. Day 10's idempotency checks all passed until a control discarded the key and produced two bookings. Day 11's short-circuit control stayed green — which is how the probabilistic failure rate was discovered.

> **A test that still passes when you remove the mechanism is testing nothing.**

When a control does *not* fire, that is a finding about the test, not permission to move on.

---

## What this does not buy you

**Layer 3 replays behaviours you have already seen.** It cannot discover what a model will do next. Ten of eleven defects here were found by a human reading a transcript, and that will remain true.

The suites stop the old defects coming back. **A person using the agent is still the only instrument that finds new ones** — so budget time for it, and read the transcript rather than the summary.
