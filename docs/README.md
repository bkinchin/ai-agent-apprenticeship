## The standard

An architecture note is worth writing only if it records a **decision and its alternatives**. A document that describes what the code does is redundant — the code does that. A document that records *why it is this way and what you rejected* is the thing you cannot reconstruct in six months.

Every note should answer:

1. What was the decision?
2. What else did you consider?
3. What does this choice cost?
4. What evidence supported it?
5. What would make you change it?
